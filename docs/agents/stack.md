# Stack card

Every pipeline stage and agent reads this file for the project's commands, pack and build mode. `/setup-project`
wrote it; edit it by hand whenever the project changes.

## Pack

- **Pack:** none. Online Boutique is eleven services in five languages (Go, C#, Java, Node, Python), none of them
  Spring Boot. Every stage and agent works the same; what's missing is stack knowledge. The standards review uses
  `CODING_STANDARDS.md` (which has a short section per language) and the smell baseline, and `/deploy` writes its
  files from the shape in its "No pack" list.
- **Plugins:** `pipeline@kits`

## Services

| Language | Services (under `src/`) | Toolchain pinned by |
|---|---|---|
| Go | checkoutservice, frontend, productcatalogservice, shippingservice | each `go.mod` (`toolchain go1.27.1`) |
| C# | cartservice (`src/` and `tests/`) | `*.csproj` (`net10.0`), Dockerfile (`dotnet/sdk:10.0`) |
| Java | adservice (Gradle, google-java-format) | Dockerfile (`eclipse-temurin:25`), `build.gradle` (source 21) |
| Node | currencyservice, paymentservice | Dockerfile (`node:24`) |
| Python | emailservice, recommendationservice, shoppingassistantservice, loadgenerator | Dockerfile (`python:3.14`) |

The services talk gRPC through `protos/demo.proto`; each service's generated code (`genproto/`, `*_pb2*.py`) is
regenerated by its `genproto.sh`, never edited by hand.

## Commands

`/setup-project` ran each command once. "not set up yet" means the project doesn't have it so far. Run each from the
service's folder (`src/<service>`) unless the command says otherwise.

| Purpose | Command |
|---|---|
| Compile or typecheck (fast) | **Go:** `go vet -copylocks=false ./...` · **C#:** `dotnet build src/cartservice/src` · **Java:** `sh gradlew -q compileJava` · **Node:** `node --check <file>.js` · **Python:** `python3 -m compileall -q .` |
| One test file | **Go:** `go test -run '^TestGetQuote$' .` · **C#:** `dotnet test src/cartservice/tests --filter "FullyQualifiedName~AddItem_New_Inserted"` · **Java, Node, Python:** not set up yet (no tests) |
| Full verify, including container tests | **Go:** `go test ./...` · **C#:** `dotnet test src/cartservice/` · **Java:** `sh gradlew build` · **Node:** `npm ci` · all of it: `.github/workflows/ci.yml`, whose `verify` job is the one check `main` requires |
| Lint and format check | **Go:** `gofmt -l . \| grep -v '^genproto/'` (must print nothing) · **Java:** `sh gradlew verifyGoogleJavaFormat` (also part of `build`; `googleJavaFormat` fixes) · **C#, Node, Python:** not set up yet |
| Module-boundary check | not set up yet (the boundary is `protos/demo.proto`; each service is its own module) |
| End-to-end tests | not set up yet (`docs/explorer/shop-session.sh` walks a shopper through the running shop, but asserts nothing) |
| Run locally | `docs/explorer/run-services.sh shop` from the repo root: all services and Redis in plain Docker, each at its memory limit from `kubernetes-manifests/`, frontend on `127.0.0.1:8080` |

Notes from running them:

- **Go:** `go vet` runs without `copylocks` until protobuf messages stop being copied by value (issue #7).
- **C# on Apple silicon:** `Grpc.Tools` ships only an x86-64 `protoc` for macOS, so the build fails with "Bad CPU
  type" unless Rosetta is installed. The commands work in the SDK container:
  `docker run --rm --memory 1536m --memory-swap 1536m -v "$PWD/src/cartservice:/work" -w /work mcr.microsoft.com/dotnet/sdk:10.0 dotnet test tests/`
- **Java:** `gradlew` isn't executable in git, hence `sh gradlew`. `gradle.properties` opens the javac internals
  google-java-format needs on JDK 16+; without it `build` fails at `verifyGoogleJavaFormat`.
- **Node:** npm 11 skips the dependencies' install scripts (`protobufjs`, `pprof`); the syntax check doesn't need them.

## Migrations

- **Tool:** none yet. The cart lives in Redis (or optionally Spanner or AlloyDB, set up by `terraform/`); no service
  owns a versioned schema.
- **Rule:** never edit an applied migration. Change schemas expand → migrate → contract, so the previous version still
  runs against the new schema and a rollback stays safe.

## Build mode

- **Default:** deliver
  - **learn:** the learner writes the code; Claude teaches and reviews.
  - **build-with-me:** the implementer writes one block of at most ~60 lines; the human checks it, answers 1–2
    questions and replies OK, CHANGE, MINE or WHY.
  - **deliver:** the implementer builds the whole ticket; the automated review loop runs before the PR.
- A ticket can override it: `/implement <ticket> deliver`.

## Pull requests

- **Base branch:** main
- **Budget:** about 400 changed lines, not counting lockfiles, generated code (including protobuf output) or
  snapshots. Over budget, `/implement` proposes a split; CI labels any larger PR `size/large`.
- **Checks not required:** go (checkoutservice), go (frontend), go (productcatalogservice), go (shippingservice),
  dotnet (cartservice), java (adservice), node (currencyservice), node (paymentservice), python (all services)
  - Checks that PRs run but `main` leaves out on purpose, separated by commas. `/setup-project protect` makes every
    other check required, and `/next` names any that isn't yet.
  - Why these: `ci.yml`'s `verify` job fails unless every one of them passed, so the ruleset requires only `verify`
    and `human-review`, and adding a service changes `ci.yml` but not the ruleset.
